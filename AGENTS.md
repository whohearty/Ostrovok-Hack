# Работа агентов над проектом
Сначала прочитайте README.md, docs/strategy.md, docs/architecture.md, docs/data-contracts.md и актуальную карточку CaseHub. В этой версии создан план; продукт ещё не реализован.

- CaseHub — статусы, владельцы, зависимости и результаты. Перед записью получать свежую revision; при конфликте перечитывать и сохранять чужие изменения.
- Владелец карточки — человек по направлению, исполнитель — агент. effort оценивает работу агента; reviewEffort — проверку человеком. Не создавать встреч по предварительным окнам.
- Использовать отдельную agent/ost-xxx ветку и артефакты по контрактам. Интеграцию независимых веток координирует Даня.
- Перед выполнением проверить завершение dependencies. Не отмечать готовность по одному созданию файла; сохранять resultNote, resultLinks, SHA, доказательства и ограничения.
- Условия организаторов, факты, расчёты, допущения и решения команды явно различать. Стратегия ассистента —draft до проверки. Не записывать гипотезы как принятые решения.
- Исходное задание, письма, приглашения, ключи, персональные данные и скрытые тесты хранить в закрытых источниках, не в открытом git. Использовать ссылки/оригинальную рабочую документацию.
- Агент не выполняет реальные оплаты/брони, не отправляет письма/сообщения и не подтверждает действия, которые не совершал. Внешняя отправка и вход в аккаунт требуют доступного инструмента и поручения владельца.
- Для кода проверять значимые инварианты:цена, время, состав группы, пересборка, изолированность сессий и повторный checkout. Для источников —provenance и правдивые метки синтетики.
- Не включать дополнительные функции, пока не работает весь обязательный путь. 28 октября приоритет —исправления, валидация и сдача.
